# 浏览器星历迁移与核验

核验日期：2026-10-29。

## 运行方式与边界

`src/astrology.js` 使用固定版本 `@kuntay/swisseph 0.2.2`，把 Swiss Ephemeris **2.10.03** 的 C 实现通过 WebAssembly 运行在浏览器中。它没有把天文算法改写为低精度 JS 近似公式，也不需要 Python 服务器或在线占星 API。

初始化调用 `await initAstrology(baseURL)`，其中 `baseURL` 指向本站的 `data/` 目录，可以位于 GitHub Pages 的项目子路径。模块只从同源读取：

- `ephe/sepl_18.se1`、`ephe/semo_18.se1`，用于 1800 年以后的日月位置。
- `ephe/sepl_12.se1`、`ephe/semo_12.se1`，用于 1800 年初出生者落在 1799 年的出生前朔望。
- 同目录 `timezones.json`，由时区模块加载的固定 `tzdata 2026.6 (IANA 2026f)` 转换表。

WebAssembly 文件随应用构建在本站加载，不使用第三方 CDN。初始化之后，`calculateBirth(payload)` 在内存中计算，不提交出生资料。手动取字模块独立于星历初始化；全自动所需文件失败时，星历模块返回明确错误，供界面保留手动输入。

本模块支持公历出生年份 1800—2100，纬度必须严格介于 −90° 与 +90°，经度包含 −180° 与 +180°。

## 与 06 原版一致的计算口径

- 日月为当日回归黄道上的地心视黄经，调用实际 `swe_calc_ut`。
- UTC 通过原生 `swe_utc_to_jd` 转为 **UT1** 儒略日，使用第二项输出；朔望时间通过 `swe_jdut1_to_utc` 转回 UTC。不把 JavaScript 的 UTC 儒略日直接当作 UT1。
- 采用 `houses(..., 'E')` 的几何上升点，不使用普拉西德宫头来间接替代上升点。
- 太阳高度直接调用 `swe_azalt`，读取无大气折射的太阳中心高度。高度大于等于 0° 判为昼生；不以太阳上缘日出、固定钟点或民用曙暮光代替。
- 朔望搜索实际日月黄经差最近的 0°／180°事件，以半日步长包围根，再二分求根。满月仍取月亮黄经。与 06 版一样，事件恰逢出生时计入该事件，数值相位容差为 `1e-8°`。
- 保留原始精度供取字模块向下取整，显示位数不参与计算。高纬、太阳接近地平线及 1900 年前的民用时间记录保留核对提示。

## 实际星历来源检查

Swiss 库本身可能在文件不可用时回退到 Moshier。浏览器模块对**每一次**日月位置计算检查 C 函数真实返回的来源标志，包括每一步朔望求根；只有 `(flags & 7) === 2`（Swiss 文件）才继续。否则拒绝全自动计算，不能把回退结果标成文件星历。

初始化另外探算 2000 年和 1799 年，确认两个文件时间块均能使用。结果元数据中的 `ephemeris_flags` 保留出生太阳、出生月亮、朔望太阳、朔望月亮四项；正常样例均为 `258`，即 Swiss 文件 `2` 加速度标志 `256`。

## 核验资料与结果

### 原版固定对照

`tests/astrology.test.js` 内保存了在 06 原版 Python／Swiss 2.10.03、相同星历文件与固定时区资料下产生的 **13 组不可变 golden 值**。测试运行只读取 JS 常量与本站数据，不运行 Python，也不实时重新生成预期值。

样例覆盖：格林尼治 J2000、上海 1988 年夏令时与冬季、纽约 2021 年重复时刻的两个选项、北纬 89° 极昼与极夜、1800 年初的 1799 年前朔望、2100 年末、2001 和 2024 年的新月与满月。

每组比较日、月、上升、朔望月亮、太阳高度、出生 UT1 儒略日、朔望 UT1 儒略日、昼夜与事件 UTC。通过阈值为：角度 `2e-7°`（0.00072 角秒），儒略日 `5e-9` 日（约 0.43 毫秒），显示到秒的朔望时刻容差 1 秒。13 组全部通过。

### 外部朔望时刻

对照来源：[NASA/GSFC《Phases of the Moon: 2001 to 2025》](https://eclipse.gsfc.nasa.gov/phase/phase2001gmt.html)。其表格给 UT 至分钟。与 06 版相同的五个参考事件（2001-01-24 新月、2001-01-09 满月、2024-04-08 新月、2024-03-25 满月、2025-02-12 满月）均通过 60 秒容差。

### 其他回归

以下测试同时通过：

- 满月使用月亮，而非太阳黄经；事件出生前后数秒和前后 **10 毫秒**的选取，不取到未来事件。
- 上海历史夏令时 +09:00，纽约春季不存在时间拒绝、秋季重复时间要求明确选择，两次 UTC 相隔一小时。
- 极昼／极夜、近地平线提示、太阳跨 360°／0° 时取整两侧的连续性。
- 非法日期、钟点、时区、布尔／字符串坐标、NaN、无穷、极大数及极点输入的拒绝。
- 初始化幂等、文件不完整时明确失败、修复文件后可重试；文件内容虽有效但装在错误年份文件名下时拒绝使用。

运行命令：

```sh
node --test tests/astrology.test.js
```

**25 项测试全部通过。** 这些验证天文迁移、时间换算及课程取字所需位置的正确衔接；不等于逐例人工核验所有出生资料。
